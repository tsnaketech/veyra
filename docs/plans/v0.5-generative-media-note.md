## 0. Résumé

- Flux par défaut : **export manuel** depuis FLORA ou Google Flow, puis **import
  validé** dans Veyra. Aucun appel cloud n'est nécessaire au POC.
- FLORA a une API REST et un serveur MCP officiels, avec devis en USD avant
  exécution [F3, F5]. Une intégration est possible plus tard, en option, avec
  autorisation explicite à chaque appel et des plafonds de dépense.
- Google Flow n'a **pas d'API documentée** dans les pages ouvertes [G1–G4]. Les
  API officielles distinctes (Gemini API, Gemini Enterprise Agent Platform /
  Vertex) sont d'autres produits [G5–G7], hors de cette note.
- HyperFrames 0.8.214 sait placer, rogner et accélérer des clips `<video>`
  [H1]. Le moteur détecte la fréquence variable (VFR) et refuse certaines
  extractions sur une source VFR [H3]. Veyra doit donc **transcoder en CFR**
  avant composition (D012).
- Nouveau type de scène `media`, provenance immuable attachée à l'asset, cache de
  rendu par scène pour les corrections localisées, et QA des médias importés en
  réutilisant les mesures existantes.

## 3. Pipeline d'import dans Veyra

Même modèle que `probeAudio` ([AUDIO-PIPELINE](../video/AUDIO-PIPELINE.md)) et
ffprobe de `@veyra/video` :

1. **Réception** : fichier régulier, sans lien symbolique, taille bornée ; original
   copié en exclusif (`packages/storage`, « originaux exclusifs ») ; SHA-256.
2. **Sonde** (`probeMedia`, nouveau dans `@veyra/video`) : le format vient de
   ffprobe, pas de l'extension. Liste fermée : MP4/MOV (H.264, H.265, ProRes),
   WebM (VP9/AV1, à confirmer), PNG/JPEG/WEBP pour les images ; GIF accepté
   seulement s'il est converti. On mesure fps rationnel (`r_frame_rate` et
   `avg_frame_rate`), durée, résolution, SAR/DAR, rotation, espace colorimétrique
   et transfert (HDR), alpha, flux audio. Puis **décodage complet** : une erreur
   en sortie de décodage rend le média invalide, même avec un code de retour zéro
   (règle `probeAudio`). Codes d'erreur alignés sur `AudioMediaError` :
   `missing`, `too-large`, `unsupported-format`, `no-video-stream`, `too-long`,
   `decode-failed`.
3. **VFR** : un média est VFR si le nombre de PTS ne correspond pas à un grille
   CFR, ou si `r_frame_rate` et `avg_frame_rate` diffèrent. HyperFrames utilise un
   écart > 10 % [H3] ; Veyra devrait être plus strict (contrôle des PTS). Un VFR
   n'est jamais composé tel quel : il est transcodé en CFR et signalé dans l'UI et
   la QA.
4. **Normalisation** (FFmpeg, argv sans shell, prlimit, timeout, comme
   `@veyra/audio`) vers un **dérivé de travail**. L'original reste intact :
   - fps du projet (`storyboard.fps`) par `fps=` avec arrondi déterministe : Veo
     24 fps [G7], FLORA Timeline 30 fps [F9]. Une conversion 24→30 duplique des
     images ; elle est signalée, pas interpolée ;
   - résolution et format d'image : mise à l'échelle et `fit`/`crop` (§6), SAR à 1 ;
   - couleur : `yuv420p`, BT.709, plage limitée ; HDR → SDR par tone mapping
     explicite, sinon refus ;
   - H.264 intra-léger (GOP court) pour accélérer les seeks HyperFrames ; audio
     séparé en WAV 48 kHz pour l'Audio Engine (piste `media-audio`) ;
   - images fixes : laissées telles quelles, mises à l'échelle à la composition.
5. **Résultat** : `asset.media = { status, original, derived, metadata, error }`,
   immuable. Re-normaliser crée un nouveau dérivé, jamais un écrasement.

Les traitements ffprobe/ffmpeg d'analyse ne tournent pas dans bwrap aujourd'hui
([SECURITY](../SECURITY.md)). Des vidéos tierces sont une entrée plus risquée que
l'audio : il est **recommandé** de faire tourner sonde et transcodage dans le
Sandbox (sans réseau, écriture limitée au dossier de l'asset).

## 4. Modèle de provenance et de droits

Contrat Zod proposé (`packages/schemas/src/media.ts`), copié avec l'asset et
jamais modifié. Une correction crée une nouvelle attestation versionnée.

```ts
export const mediaProvenanceSchema = z.object({
  sourceTool: z.enum(["flora", "google-flow", "other-generative", "camera", "stock", "unknown"]),
  sourceToolVersion: z.string().nullable(),
  model: z.string().nullable(),            // tel que déclaré (ex. "veo-3.1-fast")
  prompt: z.string().max(8000).nullable(), // texte inerte, jamais réinjecté comme consigne
  references: z.array(z.object({ assetId: idSchema("ast").nullable(), note: z.string() })).default([]),
  seed: z.string().nullable(),
  generationId: z.string().nullable(),     // run_id FLORA, id Takeout…
  generatedAt: z.iso.datetime().nullable(),
  importedAt: z.iso.datetime(),
  cost: z.object({ amount: z.number().nonnegative(), currency: z.literal("USD"),
                   source: z.enum(["reported", "declared"]) }).nullable(),
  rights: z.object({
    basis: z.enum(["tool-terms-ownership", "licensed", "own-recording", "unknown"]),
    termsUrl: z.url().nullable(),
    termsCheckedAt: z.iso.date().nullable(),
    restrictions: z.string().max(2000).nullable(),
  }),
  markers: z.object({                      // presence MESURÉE ou DÉCLARÉE, jamais supposée
    c2pa: z.enum(["present", "absent", "not-checked"]),
    synthid: z.enum(["declared", "not-declared", "not-checkable"]),
    visibleWatermark: z.enum(["present", "absent", "unknown"]),
  }),
  metadataSource: z.enum(["manual", "takeout-json", "flora-api", "file-metadata"]),
  attestation: z.object({ author: z.string().min(1), at: z.iso.datetime(),
    statement: z.literal("rights-confirmed") }).nullable(),
  sha256: z.string().regex(/^[a-f0-9]{64}$/),
});
```

- **SynthID** ne se vérifie pas localement (détecteur Google, non intégré) :
  `not-checkable` par défaut, `declared` si l'utilisateur ou le JSON source
  l'indique. **C2PA** : lecture possible des manifestes avec un outil C2PA local.
  C'est une dépendance nouvelle à évaluer (licence, taille), **non retenue pour
  le POC** (`not-checked`).
- Aucun prix n'est inventé : `cost.source = "reported"` seulement si une API l'a
  renvoyé (`charged_cost` FLORA [F3]) ; sinon `declared` ou null.
- **UI** : panneau « Provenance » sur l'asset et sur la scène (outil, modèle,
  prompt replié, droits, marqueurs, attestation) ; badge « IA générative » sur la
  timeline. **L'export final est bloqué** tant qu'un média génératif n'a pas
  d'attestation de droits.
- **QA** : contrôle « Provenance des médias ». Il est `minor` s'il manque une
  attestation ou si les droits valent `unknown`, `info` pour les marqueurs non
  vérifiables. Il n'est jamais `passed` sur la seule déclaration.

## 5. Intégration FLORA optionnelle (après le POC)

Seulement si l'utilisateur la demande, et décision à part (D0xx). Elle reprend
les principes de `claude-subscribe` (D010) et de l'enveloppe validée par phase
(D019) :

- **Mode par défaut `export-manuel`** ; un fournisseur `flora-api` n'est actif
  que s'il est configuré. La clé API (`ak_…`, permissions Read + Write
  uniquement, Billing en option pour le solde) est gérée comme les autres
  secrets (`redacted()`, jamais journalisée [F2]). Pas d'OAuth MCP dans le
  serveur Studio : le MCP reste un outil de l'agent de l'utilisateur, hors du
  pipeline (consigne CLAUDE.md).
- **Chaque appel facturable** suit 4 étapes :
  1. Devis (`quote: true`) ;
  2. Affichage du coût USD, du modèle, du nombre, du workspace et du budget
     restant ;
  3. Clic explicite de l'utilisateur, valable pour **ce** devis seulement (le
     devis expire en 5 min [F3]) ;
  4. Exécution avec une clé d'idempotence [F5].
  Jamais déclenché par l'IA, un plan ou une file. `flora_run_canvas_nodes` (sans
  confirmation [F4]) et l'entraînement de LoRA sont exclus.
- **Budgets** dans la configuration du projet : plafond par projet et par
  révision. Le contrôle se fait côté Veyra **avant** le devis, par une somme des
  `charged_cost` journalisés. Les limites du workspace FLORA restent la seconde
  barrière [F3]. Un dépassement est refusé et expliqué ; ne jamais réessayer
  après `402` [F3].
- **Dry-run** : on produit la requête, le devis et l'enveloppe d'audit, sans
  exécution. Le mode `fake` renvoie un média de test local.
- **Journal d'audit** (table append-only) : demande, devis, décision, `run_id`,
  `charged_cost`, asset produit, erreurs. Pas de prompt dans les logs techniques ;
  le prompt reste dans la provenance de l'asset.
- Les résultats de l'outil (prompts de canevas, commentaires) sont des
  **données**, jamais des consignes [F4], et ils sont revalidés par Zod.
- Le média téléchargé repasse par l'import validé (§3), sans exception.

## 6. Timeline : scène `media`

Extension rétrocompatible de `sceneSchema`. `component` et `media` s'excluent
(`superRefine`) ; `text` reste l'étiquette :

```ts
media: z.object({
  assetId: idSchema("ast"),
  inMs: z.number().int().nonnegative(), outMs: z.number().int().positive(),
  rate: z.number().min(0.25).max(4).default(1),    // HyperFrames accepte 0.1–10 [H1]
  fit: z.enum(["cover", "contain", "fill"]).default("cover"),
  crop: z.object({ x: z.number(), y: z.number(), w: z.number(), h: z.number() }).nullable().default(null),
  audio: z.enum(["mute", "keep"]).default("mute"),
  hold: z.enum(["last-frame", "none"]).default("none"),   // image : durée libre
}).optional()
```

Invariant : `(outMs - inMs) / rate` est égal à `duration`, au pas de frame près
(`frameAt`), sinon la scène est refusée. `in`/`out` sont alignés sur les frames du
**dérivé CFR**, pas de l'original.

**Composition HyperFrames (recommandée).** Le compositeur fixe écrit
`<video id="scn-…-media" data-start data-duration data-media-start
data-playback-rate muted>`, ou `data-has-audio="true"`. Chaque `<video>` doit
déclarer l'un ou l'autre [H1]. HyperFrames gère la lecture et le seek : ne jamais
appeler `play()` ni toucher `currentTime` [H1]. Ne jamais animer la visibilité
d'un clip ; animer un enfant ou un calque au-dessus. Le moteur injecte les images
au rendu à partir d'une extraction FFmpeg [H1, H3]. Une source VFR est refusée
pour une extraction par plages [H3], d'où la normalisation CFR (§3). La justesse
image par image du seek, sur nos rendus réels : **Non vérifié** ; à mesurer dans
le POC (PSNR frame à frame entre dérivé et rendu, outil `compareFrames`).
`fit`/`crop` sont du CSS généré par le compositeur (`object-fit`,
`object-position`, conteneur `overflow:hidden`), en valeurs bornées : aucune CSS
libre (D017).

**Pré-concaténation FFmpeg (repli).** On découpe et concatène les segments
`media` avec les segments HyperFrames. C'est simple et rapide si aucun calque ne
recouvre le média. Mais les sous-titres et overlays au-dessus d'un clip exigent
quand même un passage d'incrustation, et deux moteurs de composition doublent la
surface de test. À garder seulement pour le cache par scène (§8).

**Audio.** Avec `audio: keep`, le son du clip devient une piste `media-audio` de
l'Audio Engine, ancrée sur l'événement de la scène. Il n'est pas mixé par
HyperFrames : le mix reste la seule source du son (vidéo HyperFrames muette, mux
AAC).

## 7. Montage hybride

Une seule timeline déterministe, par ordre de couches :

1. Scènes : `component` (registre Motion) ou `media` (clip ou image), ordonnées
   sans chevauchement (règle actuelle du storyboard).
2. Overlays GSAP par scène (titres, bandeaux) : composants à fond transparent
   (variante `overlay` d'un composant existant, données seulement), au-dessus du
   clip.
3. Calque `.captions` v0.4 (`CaptionTrack`), quantifié sur les frames ; il
   traverse les scènes `media` comme les autres.
4. Audio : voix v0.4, musique, `media-audio`, mixés par `@veyra/audio`, ancrés
   sur des événements de scène (`anchorSchema`).

Les transitions entre un clip et une scène HyperFrames reprennent le fondu de
sortie existant (0,4 s). Pas de transition croisée dans le POC : elle supposerait
deux scènes visibles en même temps, ce que le storyboard interdit aujourd'hui.

## 8. Corrections localisées

Aujourd'hui, `reuse-video` réutilise la vidéo muette quand seul l'audio change.
On généralise à la **scène** :

- **Clé** `sceneRenderKey = sha256(scène normalisée JSON + width/height/fps +
  version du composant + sha256 du dérivé média + version HyperFrames + version
  GSAP + hash du compositeur)`.
- **Rendu** : chaque scène devient un segment HyperFrames (une sous-composition,
  ce qui règle aussi l'avertissement `nested_structure_needs_subcomposition`),
  mis en cache par clé. Le final est assemblé par le concat FFmpeg. La copie de
  flux ne marche que si l'encodage est identique et que chaque segment fait
  exactement `round(duration × fps)` images ; sinon on réencode, ce qui est plus
  lent mais déterministe.
- **Calques transverses** (sous-titres, overlays qui débordent d'une scène) : ils
  ne doivent pas casser le cache. Il y a deux options, **à trancher par mesure
  dans le POC** :
  - (a) découper les cues aux bornes de scène, chaque segment portant ses
    propres cues ;
  - (b) un passage d'incrustation final sur la vidéo assemblée, qui ré-encode
    tout mais ne recompose pas les scènes.
- **Flux** : commentaire sur une frame, puis `sceneId` déjà résolu par
  `feedback`. Le plan ne contient que des patches des scènes visées (déjà borné
  par `scenePatchSchema`). Pour une scène `media`, le patch peut :
  - changer `in`/`out`/`fit`/`crop` ;
  - remplacer l'`assetId` par un autre média importé.
  Seules les clés modifiées sont rendues. Le journal du job indique les scènes
  « réutilisées » et « rendues » (comme `videoReusedFrom`).
- Une « régénération » d'un clip génératif = un nouvel export importé manuellement,
  ou plus tard un appel FLORA autorisé (§5). Ce n'est jamais automatique.
- QA comparatif : PSNR des scènes réutilisées par rapport à la révision parente.
  Elles doivent être identiques ; un écart est une régression `major`.

## 9. QA et révisions

| Contrôle | Mesure (existante ou proposée) | Échec |
|---|---|---|
| Média — flux | codec, profil, résolution, SAR, rotation, HDR (ffprobe) | `major` si invalide |
| Média — CFR | VFR à l'import, CFR du dérivé (`assertConstantFrameRate`) | `major` si dérivé VFR |
| Média — durée | `(out-in)/rate` vs durée de scène, ± 1 frame | `major` |
| Média — images noires / figées | `blackdetect` (déjà utilisé), `freezedetect` (nouveau) sur la plage | `minor` |
| Média — audio conservé | ebur128 / silences / écrêtage de l'Audio QA v0.3 | inchangé |
| Photosensibilité | `detectFlashes` T104 sur le rendu final | gravités T104 |
| Fidélité du clip | PSNR dérivé vs rendu sur N frames | `minor` |
| Provenance | attestation, droits, marqueurs (§4) | `minor` / `info` |
| Filigrane visible | déclaré par l'utilisateur, non détecté | `info` |

La photosensibilité garde ses limites documentées (aucune certification, pas de
flash rouge saturé, pas de motifs, comptage global :
[QUALITY-STANDARDS](../video/QUALITY-STANDARDS.md)). Les clips génératifs sont
plus exposés à ces cas que les composants maison ; le rapport le rappelle.

Les assets média sont immuables : original, dérivé et provenance. Une révision
référence des `assetId` et des sha256, jamais un chemin modifiable. La
validation humaine reste obligatoire, comme les jugements IA séparés des mesures
(D015). « Revue visuelle du clip » reste `not-performed` tant qu'aucun humain
ne l'a vue.

## 10. Architecture minimale, dépendances, risques, POC

```text
Export manuel FLORA / Flow ──▶ Studio.importMedia
  (optionnel plus tard :           │  original exclusif + sha256
   FLORA API, devis + clic) ──────▶│
                                   ▼
                @veyra/video probeMedia (sandbox) ── invalide → refus expliqué
                                   │ valide
                                   ▼
                normalizeMedia (FFmpeg) → dérivé CFR (fps projet, BT.709, yuv420p)
                                   │            └─ media-audio WAV → @veyra/audio
                                   ▼
                Asset { media, provenance (immuable) }
                                   │
Storyboard: scènes component | media ─▶ compose.ts (vidéo, overlays, captions)
                                   │
                                   ▼
                HyperFrames (bwrap, sans réseau) ─ segments par scène (cache par clé)
                                   │
                                   ▼
                concat FFmpeg → mux audio → QA mesurée + provenance → validation humaine
```

**Dépendances nouvelles** : aucune pour le POC (FFmpeg/ffprobe, HyperFrames,
Zod déjà présents). Plus tard, en option : lecteur C2PA local, à évaluer
(licence, taille) ; SDK FLORA inutile, l'API REST suffit.

**Risques.**
- **Conditions** : les droits FLORA renvoient aux modèles tiers sans les
  détailler [F7]. Les CGU complètes de Flow ne sont pas vérifiées [G1]. Les
  conditions changent, d'où `termsCheckedAt` et l'attestation obligatoire.
- **Coût** : une exécution échouée est gratuite mais un nouvel essai est
  refacturé ; le devis n'est pas un prix garanti [F3]. Mitigation : budgets côté
  Veyra, aucun nouvel essai automatique.
- **Filigranes** : un filigrane visible imposé dans certaines régions [G1] reste
  dans le rendu final. SynthID n'est pas vérifiable localement. Veyra ne retire
  jamais un filigrane.
- **VFR et fps** : Veo 24 fps [G7], FLORA Timeline 30 fps [F9], fps de Flow non
  vérifié. Les conversions dupliquent des images, ce qui peut produire des
  saccades à revoir à l'œil.
- **Pérennité des API Google** : modèles preview arrêtés [G5], retrait annoncé
  pour les modèles GA [G7]. C'est une raison de plus de ne pas en dépendre.
- **Sécurité** : décodeurs FFmpeg exposés à des fichiers tiers ; sandbox
  recommandé (§3).
- **Seek HyperFrames** : précision image par image sur nos rendus non vérifiée.

**POC proposé (sans appel cloud).** Entrées : un export FLORA (MP4 H.264, fourni
par l'utilisateur) et un export Flow (MP4, fourni par l'utilisateur), placés à la
main dans un dossier local. Le POC ne fait aucune génération.

1. `probeMedia` + `normalizeMedia` sur les deux fichiers, plus un cas VFR
   synthétique produit localement par FFmpeg.
2. Storyboard 1080p 30 fps : scène `media` (FLORA, rognée `in/out`), scène
   `animated-title`, scène `media` (Flow, `fit: contain`). Un `CaptionTrack` v0.4
   en `timing: scene` traverse les trois.
3. Rendu HyperFrames sous bwrap, puis QA, puis validation humaine dans le Studio.
4. Correction localisée : on change le `in` du clip Flow. Seule cette scène est
   re-rendue, si l'option cache est implémentée ; sinon on mesure le temps total.

**Critères d'acceptation.**
- Les deux exports sont importés avec original et sha256 ; l'original n'est pas
  modifié (même sha256 après traitement).
- Le dérivé est CFR au fps du projet (`assertConstantFrameRate`). Le cas VFR est
  détecté, signalé et normalisé.
- Rendu final : nombre d'images = `round(durée × fps)`. Chaque scène `media`
  commence à la frame attendue, ± 0 frame, mesurée par PSNR. La moyenne
  dérivé/rendu est ≥ seuil à fixer au POC.
- Les sous-titres apparaissent à ± 1 frame de leur SRT sur les scènes `media` et
  HyperFrames.
- Le panneau provenance s'affiche ; l'export est bloqué sans attestation ; le
  contrôle « Provenance » est présent dans le rapport.
- Photosensibilité, noir/figé et durée produisent un verdict ou `not-performed`
  motivé. Aucune vérification n'est présentée comme réussie sans mesure.
- Aucun accès réseau pendant le POC (bwrap sans réseau, aucun client HTTP
  appelé).
- Après correction localisée : PSNR identique sur les scènes non touchées, et
  temps de rendu mesuré comparé au rendu complet.

**Décisions à demander à l'utilisateur** :
- l'option (a) ou (b) pour les calques transverses ;
- le sandbox pour ffprobe/ffmpeg d'import ;
- l'intégration FLORA API (oui/non, budgets) ;
- le blocage de l'export sans attestation.
